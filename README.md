# Bizim — AI-платформа для малого бизнеса Казахстана

Рабочий MVP, не шаблон. Каждая кнопка выполняет реальное действие:
регистрация идёт через настоящий Supabase Auth, импорт файлов реально
парсит CSV/Excel/JSON, AI-анализ и AI-чат реально вызывают OpenAI API
и ничего не выдумывают — если данных не хватает, интерфейс так и пишет
«Недостаточно данных», вместо того чтобы рисовать случайные графики.

## Честное замечание про стек

В задании указан Next.js 16 — на момент сборки этого проекта последняя
стабильная версия Next.js — 15.x, поэтому `package.json` использует её.
Как только выйдет 16-я версия, апгрейд делается штатно (`npm i next@latest`),
архитектура (App Router, Server Components, Route Handlers) не изменится.

## Что нужно, чтобы всё заработало

Без ключей ниже проект **честно показывает сообщение**, что нужно подключить
сервис — никакой имитации функционала.

1. **Supabase** (обязательно для регистрации, кабинета, импорта)
   - Создайте проект на https://supabase.com
   - Выполните `supabase/schema.sql` целиком в SQL Editor — это создаст
     таблицы `businesses`, `imported_files`, `ai_analyses`, `chat_messages`
     и включит Row Level Security, чтобы каждый пользователь видел только
     свои данные.
   - Скопируйте `.env.example` в `.env.local` и заполните
     `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
     `SUPABASE_SERVICE_ROLE_KEY` (последний — из Project Settings → API,
     используется только на сервере).

2. **OpenAI API** (обязательно для AI-анализа и AI-чата)
   - Получите ключ на https://platform.openai.com/api-keys
   - Впишите его в `.env.local` как `OPENAI_API_KEY`.
   - Без него `/api/analyze` и `/api/chat` вернут понятную ошибку с кодом
     `OPENAI_NOT_CONFIGURED`, а не фейковый ответ.

## Установка и запуск

```bash
npm install

```

Откройте http://localhost:3000

## Как устроен реальный функционал

- **Регистрация** (`src/app/register/page.tsx`) — `supabase.auth.signUp`
  создаёт настоящего пользователя, затем строка вставляется в таблицу
  `businesses` со всеми полями из ТЗ (имя, тип бизнеса, город,
  сотрудники, клиенты за день/неделю/месяц/год, проблема, средний чек,
  рабочие часы, часы пик).
- **Импорт файлов** (`src/services/fileParser.ts`, `src/app/api/import/route.ts`) —
  CSV парсится через PapaParse, Excel — через SheetJS (`xlsx`), JSON —
  через `JSON.parse`. Результат реально сохраняется в Supabase
  (`imported_files.parsed_data`, jsonb).
- **AI-анализ** (`src/lib/analytics.ts`, `src/app/api/analyze/route.ts`) —
  сначала на нашей стороне честно считаются реальные метрики
  (выручка, клиенты, средний чек, лучший/худший день, разбивка по дням
  недели) из загруженного файла. Эти цифры передаются в промпт OpenAI —
  модели явно запрещено придумывать другие числа. Отчёт от OpenAI
  сохраняется в `ai_analyses` и в `businesses.last_analysis`.
- **AI-чат** (`src/app/api/chat/route.ts`) — история хранится в таблице
  `chat_messages` и на каждый запрос подгружается из базы (а не из
  памяти сервера), поэтому OpenAI действительно помнит предыдущие
  сообщения в рамках бизнеса.
- **Дашборд** (`src/components/DashboardCharts.tsx`) — Recharts рисует
  только то, что реально вычислено; если нужной колонки в файле нет —
  показывается «Недостаточно данных», а не выдуманный график.
- **Безопасность** — `supabase/schema.sql` включает RLS на всех
  таблицах: политики `auth.uid() = user_id` гарантируют, что пользователь
  не может прочитать чужие данные даже при прямом запросе к Supabase.

## Формат файла для импорта

Чтобы дашборд и AI-анализ увидели выручку/клиентов по дням, используйте
колонки (регистр не важен, можно на русском или английском):

| date       | revenue | clients |
|------------|---------|---------|
| 2026-07-01 | 45000   | 32      |
| 2026-07-02 | 38000   | 27      |

Если колонок с датой/выручкой нет — импорт всё равно сохранит файл,
но графики честно покажут «Недостаточно данных».

## Структура проекта

```
src/
  app/            # страницы и API-роуты (App Router)
  components/     # переиспользуемые UI-компоненты
  lib/            # supabase-клиенты, zod-схемы, openai-клиент, аналитика
  services/       # парсинг файлов
  types/          # общие TypeScript-типы
supabase/
  schema.sql      # таблицы + RLS-политики
```
